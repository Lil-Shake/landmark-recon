# 照片重建 · 地标 / Landmark Reconstructions from Public Photos

用公开的 CC 许可照片（Wikimedia Commons、Flickr）重建的带米制比例的 3D 地标模型，以及可在浏览器里旋转、量距、与真实照片逐张对比的查看页面。

Metric-scale 3D reconstructions of landmarks built only from openly licensed photos (Wikimedia Commons, Flickr), with browser viewers for orbiting, measuring and comparing against each source photo.

## 3D 模型 / Models

`models/` 里是完整分辨率的 GLB（glTF 2.0 二进制）。单位为米，+Y 朝上，原点在底部中心；顶点属性 `_EVIDENCE` 记录每个顶点被几张照片看到。

## 方法 / Pipeline

整条流程只用公开照片和一个公开的官方尺寸，不用激光扫描、无人机或任何生成模型。核心工具是 COLMAP（运动恢复结构 + 多视图立体）、Blender、trimesh 和 pymeshlab，全部在无图形界面的 Linux 集群上跑。下面以乐山大佛为例，数字来自 v6.1（110 张）和 v7c2（251 张）两次运行。

### 1. 收集照片并记录来源

- 从 Wikimedia Commons 的分类树（深度 2）和全文搜索抓取照片，下载 2400 px 的版本；v7 起再通过 Openverse API 补充 Flickr 上的 CC 照片（通常 1024 px）。
- 只接受允许演绎和商用的许可证：CC0、公有领域、CC BY、CC BY-SA。禁止演绎（ND）的照片不能用，因为 3D 重建属于演绎作品；非商用（NC）的也排除。
- 每张照片的标题、作者、许可证和来源页面在下载时就写入索引，后面每一步都带着它走，最终生成 [ATTRIBUTION.md](ATTRIBUTION.md) 和页面里的署名。

### 2. 人工筛选

把所有照片拼成带编号的缩略图表，逐张看过后剔除两类：不是拍摄对象的（别的建筑、指示牌、地图、纯人像、室内）和完全重复的。斜拍、有雾、只拍到局部的照片都保留，因为正是这些照片把不同视角连接起来。乐山大佛第一轮筛出 120 张。

### 3. 稀疏重建：求出每张照片的相机位姿

- 特征提取：GPU SIFT，每张最多 16384 个特征，长边缩到 2400 px。网络照片来自不同相机，所以每张照片单独估计一个相机模型（SIMPLE_RADIAL）。
- 匹配：两两穷举匹配，开启引导匹配。
- 增量式建图（mapper），允许生成多个子模型，取注册照片最多的那个。
- 乐山大佛 120 张里有 110 张注册成功，得到 5.4 万个稀疏点。GPU 上约 7 分钟。

### 4. 稠密重建和网格化

- 去畸变后做 PatchMatch 多视图立体（开启几何一致性，窗口半径 5，迭代 5 次，长边 2000 px；照片多时降到 1600 px 以控制时间）。
- 深度图融合成点云，要求每个点至少被 3 个像素支持。乐山大佛 v6 得到约 420 万个点。
- Poisson 表面重建（八叉树深度 11，trim 7），取最大连通块，减面到约 40 万面。
- 这是最慢的一步：110 张照片在单块 GPU 上约 1 小时。

### 5. 摆正坐标系并定米制比例

- 坐标系：+Y 取所有相机「上方向」的平均，+Z 取水平面内朝向拍摄者的方向，原点放在模型底部中心。
- 平均相机上方向有偏差风险：如果照片大多从同一侧仰拍，坐标系会倾斜。镰仓大佛就倾斜了 11.3°，需要改用台座顶面拟合出的平面法线来校正。做法是每次都渲染一张侧面正交图，检查平台是否水平。
- 比例：照片重建本身没有绝对尺度，需要一个权威尺寸。在正交渲染图上量出同一段跨度，比例 = 实际米数 ÷ 模型单位数。
  - 乐山大佛用通高 71 m（UNESCO 世界遗产 779 号的 ICOMOS 1996 评估），得到 18.07 m/单位。
  - 再用次要尺寸交叉检验：头高在模型上量得 15.0 m，公开资料为 14.7 m，相差 +2%。
  - v7 没有重新量，而是用与 v6 共有的 110 张照片的相机间距换算过来（四分位 17.97–18.18 m/单位）。

### 6. 清理和补洞（在贴图之前）

Poisson 重建会把一切都连成面，其中很多不是文物本身。清理规则都以米为单位，所以必须在定完比例之后做：

1. **删掉拍摄者身边的东西**：距任一相机中心 3 m 以内、且高于其脚面（相机高度减 1.2 m）的面。这些是栏杆、旁边的游客和树枝，从该照片的机位渲染时会挡住视线。脚面以下的地面保留。v6 删了 6886 个面。
2. **删掉臆造的表面**：离稠密点云超过 5 m 的面，是 Poisson 在没有深度测量的地方补出来的。
3. **删掉碎片**：少于 500 个面的连通块。
4. **自由空间雕刻**（v7c 起）：如果至少 2 张照片的至少 3 条视线穿过某个面才看到它后面的点，说明这个面并不存在，删掉。用来去除相机前方的薄片和鼓包。
5. **补洞**：只封闭周长不超过 40 m 的边界环（扫描的外边界和大片天空缺口远比这长，保持敞开），把补片细分到周围的边长并做拉普拉斯平滑。
6. **重新统计证据**：对每个顶点数有多少张注册照片能看到它（投影加遮挡射线检测），并标记哪些顶点是补洞生成的。

这些阈值是按 71 m 的摩崖像定的。11 m 高的独立佛像（镰仓）需要约 1.0 m 和 0.5 m；流程里可以按模型高度自动推算（分别取 0.04 和 0.045 倍高度）。独立物体头顶还会残留一层天空颜色的壳（镰仓头顶多出 0.6 m），需要按点云颜色识别后删除。

先补洞再贴图是有意的：某个位置在一张照片里被游客挡住，在另一张里可能看得见，这样补片仍能得到真实的颜色。

### 7. 照片贴图烘焙

贴图只来自注册成功的真实照片：

- 对每个纹素，先由 UV 栅格化得到它的 3D 位置，再投影到每张照片；只有当该纹素朝向相机、且是那条视线上的第一个表面（用光线投射的深度图判断）时才采用。
- 权重 = 视角余弦的平方 × 像素密度，取最好的 5 个视角混合。
- **遮挡物剔除**：某个视角的颜色与多数视角相差超过阈值（RGB 距离 0.15）就丢弃，用来去掉游客、树枝留下的重影。
- **逐张色彩校正**：这些照片跨越不同季节、天气和白平衡，所以先在重叠纹素上为每张照片拟合一个 3×3 矩阵加偏移（向单位阵正则，迭代 3 轮），使它们向加权共识靠拢。
- **多频段混合**：低频取所有视角的平均，细节取最佳视角，避免接缝。
- 没有任何照片看到的纹素用金字塔 pull-push 从邻近填色以免出现接缝，但证据计数保持为 0。
- 输出 8192² 的贴图。v7c2 有 91% 的纹素至少被 1 张照片看到，中位数 40 张。

### 8. 验收：从每张照片的机位渲染

- 在 Blender 里按每张注册照片的位姿和内参渲染模型（贴图不打光，只比较几何和贴图），与原照片左右并排。
- 逐对检查并各写一句差异。乐山大佛 v5.1 的 110 对里 101 对吻合、9 对部分吻合、0 对失败；v2 时曾有 23 对失败，主要原因是拍摄者身边的几何挡住了视线，第 6 步的规则就是为此加的。
- 这些照片同时用于贴图，所以这是自洽检查，不是留出检验。
- 另外用 Khronos glTF 校验器检查文件，并独立量一遍包围盒和面数。

### 9. 导出和网页版

- 完整模型导出为 GLB：单位米，+Y 朝上，带 `_EVIDENCE`（照片数）顶点属性。
- 网页版减面到 20–45 万面、贴图缩到 4096²，并附最多 72 张对比照片及其相机位姿。
- 页面用 three.js 渲染，提供照片贴图、纯几何、证据三种显示，两点量距，以及跳到任一照片机位做滑动对比。

### 各模型的差异

| 模型 | 与上述流程的不同 |
|---|---|
| 乐山大佛 v6.1 | 110 张 Commons 照片；无雕刻；90% 面积有照片证据 |
| 乐山大佛 v7c2 | 251 张（加 Flickr）；稠密重建 1600 px；自由空间雕刻 + 针孔补洞；85% 面积有证据 |
| 镰仓大佛 | 261 张；用台座平面校正倾斜；删除头顶天空壳；阈值按高度缩小 |
| 金阁寺 v1 | 514 张；屋顶边缘有天空色毛边 |
| 金阁寺 v2 | 全分辨率稠密重建 + 天空遮罩 + 雕刻 + 8K 贴图；天空毛边减少 56%，但孔洞变多 |

## 已知问题 / Known limitations

- 照片拍不到的区域（头顶、背面、被遮挡处）没有几何证据；页面的「证据」模式会标出这些区域，补洞面以紫色显示。
- 金阁寺两个版本质量都偏低：v1 屋顶边缘有天空色毛边，v2 毛边少但孔洞多。
- 包围盒包含崖壁和平台，所以比佛像本身大。
